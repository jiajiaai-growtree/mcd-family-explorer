# 麦麦家庭探索

## 这个 Skill 在干什么

家长带孩子进麦当劳，通常只有两个结果：吃了一顿，或者玩了一场。这个 Skill 让它多出第三个结果——**孩子看见了点什么**。

它不查优惠、不算热量、不推荐套餐。它只做一件事：**给这一趟配一张任务卡。**

## 为什么这件事值得做

麦当劳门店是一个孩子能走进去的、完整且标准化的真实系统：有供应链、有岗位分工、有严格的作业顺序、有食品安全规矩。而孩子平时只以"消费者"的身份进来，汉堡在他眼里像是凭空出现的。

任务卡要做的，就是把他从"吃的人"的位置，挪到"看的人"的位置上。

## 执行流程

### 第 0 步：先确认时间和地点

调用 `now-time-info` 拿到当前日期。**这一步不能省**——否则可能推荐已经过去的场次。

如果用户没说具体门店，用 `query-nearby-stores` 反推所在区域。

### 第 1 步：查有没有活动（可选路径）

1. `query-party-city` → 这个城市开不开放主题活动？
2. 有 → `query-party-store` → `query-partystore-date` → `query-partystore-session`
3. 按**孩子年龄**筛掉不适合的场次，只留能去的
4. 家长确认后，`party-order-create` 下单

顺手可以查一下：`campaign-calendar`（当期活动能否叠加）、`query-store-coupons`（有没有券）。

**这一步查不到活动，完全不影响交付。** 直接进第 2 步。

### 第 2 步：出任务卡（主线，任何一次进店都能用）

按 `references/任务卡模板.md` 的格式输出。四个必填项：

| 项 | 要求 |
|---|---|
| **这一趟适合谁** | 孩子年龄 + 一句"这个年纪去会看到什么" |
| **去之前问他** | **只一个问题**，要能让他猜、能让他到现场验证 |
| **现场让他看** | **两个观察点**，不要求记，看到了就够 |
| **回来让他记** | **一个产出**，二年级以下不要求写字，用画或说 |
| **家长版** | 这件事对孩子有什么用，**必须标明是我们的判断** |

### 第 3 步：存进记录本

把这张卡按日期存到用户指定的本地记录文件里，攒成"孩子看见了什么"。

## 硬规则（违反即失效）

**① 事实与判断必须分开写，并标明是谁说的。**

活动事实（年龄、时长、内容）只能来自公开可查的来源；教育解读必须写明"这是我们的判断，不是活动方承诺"。混在一起写，这张卡就废了。

**② 不编。拿不准就标"待确认"。**

不知道的年龄门槛、不确定的环节，宁可标"待确认"，也不要写一个看起来合理的数字。一张卡里出现一个编的细节，整张卡就不可信了。

**③ 不复制来路不明的活动文案。**

用户贴来的活动截图、转发文字，只用来**判断这趟值不值得去**，不原样搬进卡里。要引用事实，必须能指到公开出处。

**④ 不问不答。**

家长没问"值不值"，就别评价值不值。卡是给他用的工具，不是给活动写的好评。

**⑤ "研学"这个词分场合用。**

对家长说话时不用——说"这趟孩子能看见什么"，不说"这是一次研学"，术语是负担。**引用官方文件原话时可以用**，那是官方语言（如《"人工智能+教育"行动计划》里的"研学实践"）。分场合，不是一刀切。

**⑥ 只问一个问题。**

问三个问题，孩子一个都不会想。卡上永远只有一个问题。
