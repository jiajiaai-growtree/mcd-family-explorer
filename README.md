# 麦麦家庭探索 · mcd-family-explorer

> **别的麦当劳 Skill 在帮人怎么吃得更划算。**
> **这个 Skill 在帮一个家长，把他带孩子进麦当劳的那两小时，变成孩子的一次观察。**

麦当劳的儿童活动本来就在教真东西——探秘厨房、看后厨流程、当一日员工。但它卖的是那一小时，从不管核销之后：孩子看见了什么、想明白了什么、带回家什么。

这个 Skill 补的就是那一段。

---

## 目标用户

**一个带孩子的人。** 具体地说：

- 孩子 4–12 岁（能听懂"为什么"，也能自己动手）
- 会带孩子去麦当劳，但去完就完了，除了吃没留下什么
- 想让孩子看见点真东西，但不知道该让他看什么、又该怎么开口问

说清楚一点：**这个 Skill 不是给"想吃麦当劳的人"的。** 那个需求已经有几十个作品在做，而且做得比我们好。这里服务的是一件事——带孩子出门的那个人，和出门的那个孩子。

---

## 使用示例

### ① 有活动的时候

> **家长**：周六想带 7 岁的儿子去麦当劳，成都有没有适合他的活动？

Skill 会：

1. 用 MCP 查成都可办主题活动的门店；有的话继续查可预约日期和场次
2. 按孩子年龄筛掉不适合的场次，只留能去的
3. 出一张**任务卡**——去之前问他一个问题、现场让他看两件事、回来做一个产出

### ② 没有活动的时候（更常用）

> **家长**：今晚就带他去楼下那家麦当劳吃个饭。

Skill 直接出任务卡，**不依赖有没有活动**。因为每一家麦当劳都在运转，都够看：

| | |
|---|---|
| **去之前问他** | 一个汉堡，从地里的麦子和菜、农场里的牛，一路摆到你面前，要经过多少人的手？ |
| **现场让他看** | ① 后厨里有哪些岗位、谁在做什么　② 一份汉堡要经过几步才出餐 |
| **回来让他记** | 画一张《一家麦当劳是怎么运转的》 |

这三个问题不需要任何额外条件——**走进任意一家门店就能用**。这是这个 Skill 和别的作品最大的区别：它不是查活动用的，它是每次出门都能用的。

### ③ 攒起来

每张卡存在本地，慢慢变成一本"孩子看见了什么"的记录本。

## 安装方法

### 第一步：申请麦当劳 MCP Token

1. 打开 **open.mcd.cn**，用中国大陆手机号验证登录
2. 点右上角「控制台」→ 点「激活」→ 阅读并同意服务协议
3. Token 申请成功后一键复制

### 第二步：配置 MCP

在 WorkBuddy 左侧边栏进入「专家 · 技能 · 连接器」→「连接器」页签 → 右上角「自定义连接器」→「配置 MCP」，填入以下内容（把 `${MCD_MCP_TOKEN}` 换成你的真实 Token）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

保存后回到「自定义连接器」，把 `mcd-mcp` 设为「启用」。

> 仓库里的 `mcp-config.example.json` 是脱敏版本，只含环境变量占位符，不含真实 Token。

### 第三步：安装本 Skill

把 `skill/` 目录放进 WorkBuddy 的技能目录，或在对话中直接引用 `skill/SKILL.md`。

## 为什么这件事非麦当劳不可

能让孩子做职业体验的地方不少——博物馆、工厂、农场都在做。但麦当劳有一个别人给不了的东西：**一套被反复打磨、稳定到可以当教材讲的标准化作业流程。**

这不是形容词。在麦当劳，员工要先上完 QSC（品质、服务与清洁）课程并通过考核，才能站上调理工作站；生食戴蓝手套、熟食戴白手套，为的是防交叉污染；接触食品的器皿每四小时清洁消毒一次；炸油每天检测两次极性组分。这套东西被写进手册、被反复审计，所以它**稳定到孩子进去看到的，和说明书上写的一模一样**。

（麦当劳自己就在把门店当"实景课堂"开放。温州大学、武汉华夏理工学院、贵州师范学院、广东科技学院等院校的开放日报道里，"观摩标准化、规范化的运营流程""食品安全管控""出餐动线设计"是反复出现的原话——只是它开给大学生看，还没开给小孩看。）

**所以孩子在这里能做的事，本来就不止"吃"和"开派对"：**

| 他能做的 | 为什么只有这里能做 |
|---|---|
| 职业体验 | 站到柜台后面，做一次迎宾、点餐、送餐——从"被服务的人"换成"服务的人" |
| 流程探访 | 从前厅走到后厨，看清一个汉堡要按什么顺序经过几个人 |
| 系统认知 | 看见一家店背后那条从田间到餐桌的链 |
| 聚会 / 派对 | 官方本来就在经营的场景 |

对比一句：消防员体验营本身是很好的活动，但它换到任何一个消防队都能办，麦当劳在里面只是个场地。而"在麦当劳当一天员工""探访麦当劳的流程"，只有麦当劳能发生。

这是选题的全部理由——**不是它更好玩，是它是别人抄不走的那个。**

## 一张任务卡长什么样

家长拿到的不是一份介绍，是一张卡。卡的载体可以是任何一次进店，格式固定：

| | |
|---|---|
| **这一趟适合谁** | 孩子的年龄，以及"这个年纪去会看到什么" |
| **去之前问他** | 一个问题，带着去 |
| **现场让他看** | 两个观察点，不要求记 |
| **回来让他记** | 一个产出，不要求写字 |
| **家长版：这一趟在练什么** | 这件事对孩子真正的价值（**标明是我们的判断，不是活动方承诺**） |

空白模板与完整示例见 `skill/references/任务卡模板.md`。

**这张卡的全部功夫，在"分离"两个字上。** 活动事实只放公开可查的部分，一个字都不能自己编；教育解读必须标明是谁说的。合在一起写，卡就废了——家长分不清哪句是活动方的承诺、哪句是别人的观点。

## 用到的 MCP 能力

| Tool | 用在哪 |
|---|---|
| `now-time-info` | 先确定今天是几号，避免推荐过期的场次 |
| `query-nearby-stores` | 家长没说具体门店时，用附近门店反推 |
| `query-party-city` | 查这个城市有没有主题活动 |
| `query-party-store` | 查该城市哪些门店能办 |
| `query-partystore-date` | 查门店可预约的日期 |
| `query-partystore-session` | 查指定日期的场次 |
| `party-order-create` | 家长确认后下单 |
| `campaign-calendar` | 查当期活动，看能否叠加 |
| `query-store-coupons` | 看有没有券，降低实际花费 |

调用原则：**先筛后推**，且**先查后卡**。先按城市和年龄把不可能的去掉，再出任务卡；**没有活动也要出卡**——这条路径才是主线。

详细调用流程见 `MCP_INTEGRATION.md`。

## 待验证

- `query-party-city` / `query-partystore-session` 返回的数据里**是否带年龄字段**。带，"按孩子年龄自动筛"就能做；不带，需要自建活动—年龄对照表。
- MCP 的主题活动链路**是否覆盖"职业体验／门店探访"类活动**，还是只覆盖派对、品鉴会。
- 上面两条都不影响主线：**没有活动时出任务卡**这条路不依赖 MCP 的主题活动链路，任何门店都能用。
